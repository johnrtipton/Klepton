# PR #1 performance validation and follow-up

Reviewed `ce74582cb1e434db210014dbcd0ca0aad0e46ba2` →
`4b6809767623f3ca70f810256cbf866f60d203e9` on 2026-10-11.

## Review findings fixed in the follow-up

1. **JNI cache publication is a C data race.** The PR reads `b` before reading
   `b_cache`, and writes both without synchronization on the first invocation.
   Identical computed values do not make concurrent reads/writes legal or
   ordered. A caller can observe a ready flag alongside the old NULL pointer
   and take the unimplemented-method path. Resolve the immutable binding under
   the existing interning lock, before handing out the ID; calls then read only.
   Negative resolutions and fields still have NULL bindings.
2. **OVR index publishes its key before its value.** A reader can match the
   newly visible name while its slot is still zero. Acquire on the slot does
   not prevent observing its old value. Store the slot first, then release-store
   the name; readers acquire-load the name before reading the slot.
3. **Shim index violates effective-type aliasing.** An index entry with its
   own anonymous struct type is accessed through `kl_entry *`. Identical layout
   does not make these C types compatible. Use `kl_entry` as the index type,
   especially before increasing optimization.
4. **The O2 gate script can return success after failure.** Build failures
   continue to the next gate, and runtime statuses are printed without being
   propagated. Delegate to the fail-fast `make check-host-O2` target, using the
   Makefile's runtime source list. The new suite also includes the trace gate.

The new pthread diagnostic latch also uses relaxed atomics because different
guest threads initialize/read it concurrently.

## Measured performance

Same runtime benchmark on the base and follow-up, at `-O1`. Base received only
the PR's Makefile/CoreAudio and no-MoltenVK stub fixes to make it build, plus
the identical benchmark source. Three fresh runs, each best of five rounds,
200,000 operations. Table is the mean of the three best-round results in ns/op.

| Operation | Base | Follow-up | Ratio |
|---|---:|---:|---:|
| shim hit | 721.29 | 11.19 | 64.5× |
| shim miss | 1600.95 | 175.78 | 9.1× |
| JNI dispatch | 782.26 | 26.42 | 29.6× |
| OVRPlugin get | 70.40 | 25.24 | 2.8× |
| contended mutex | 96.79 | 52.78 | 1.8× |
| uncontended mutex | 23.08 | 22.72 | essentially unchanged |
| empty epoll poll, capacity 64 | 13774.76 | 13610.13 | essentially unchanged |

The shim/JNI/OVR gains reproduce. Mutex improvements vary with scheduling;
the claimed uncontended 1.44× improvement did not reproduce here.

The live `audio_convert` benchmark **skips** here: no output AudioComponent.
It measures the whole write path, including peak detection, ring operations
and possible producer pacing, rather than just conversion. The new
`t_audio_convert` instead calls the actual private production converter without
opening a device and compares it with the old interpolation algorithm over
500 random rate/channel/carry cases plus an explicit nonzero stereo carry.

Isolated production converter, ns per 1024 stereo frames, three timings:

| Version | Measurements | Median |
|---|---|---:|
| base, O1 | 2604.80, 2478.40, 5376.35 | 2604.80 |
| PR converter, O1 | 634.05, 636.30, 647.15 | 636.30 |
| same converter, O2 | 126.00, 121.50, 134.70 | 126.00 |

This validates about 4.1× less converter time from the fast path and a further
5.0× at O2. These are **not** full-write, end-to-end audio latency or FPS results.
There was also a large outlier in the third O2 dispatch benchmark run; no
additional O2 dispatch improvement is claimed. Raw logs are retained locally
under `context/terminal/`.

## Further changes

- Build the shipping visionOS C runtime at O2, retaining debug information.
  Makefile changes invalidate both platform archives so existing O1 archives
  cannot silently survive the flag change. The host default remains O1.
- Use a bounded 64-event stack buffer for common epoll waits. Larger requests
  retain the heap path. Readiness results, user data, empty polls, invalid size
  and bad descriptor handling are tested on both sides of the boundary. This
  eliminates allocator calls; timing is within noise, so no speedup is claimed.
- Extend the benchmark with an actual empty epoll poll and correct the
  `kl_audio_close` declaration to match its void return type.
- Add an eight-thread index test covering all 512 slots, collisions, duplicate
  content lookups, saturation, and shared JNI dispatch.

## Verification and limits

- All 12 guest-free gates pass at O1 and O2: variadic, fault, haptics,
  softinput, xrspace, xrinput, trace, ctr, bcast, hevc, audio_convert,
  perf_safety. The O2 binaries also pass with `KL_TRACE_MTXWAIT=1`.
- O2 runtime archives compile and all-load link for visionOS device and
  simulator without MoltenVK headers (the fallback branch).
- Both O2 runtime slices also compile and all-load link with the installed
  MoltenVK headers, exercising the full Vulkan implementation at build time.
- Three staged Beat Saber guest libraries load without executing constructors:
  libunity (412 bound, 1 unresolved `ptrace`), libil2cpp (301 bound, 0
  unresolved), lib_burst_generated (2 bound, 0 unresolved). This checks loader
  operation only; it does not prove guest initialization or gameplay.
- No headset gameplay/frame-time comparison or live audio validation has been
  performed. A connected Vision Pro was discovered; actual playing requires
  headset interaction. No installed game was replaced or launched by this review.
- The full `make check` requires guest assets/initialization and ANGLE beyond
  the guest-free gates. The new gates do not replace its compatibility coverage.

## Highest-value next gameplay work

1. Measure Vulkan's per-frame `QueueWaitIdle` duration and replace it with a
   GPU-to-GPU completion dependency plus safe texture lifetime. Simply removing
   the wait loses the current guarantee that the compositor samples completed
   guest rendering. Validate with a Vulkan guest and Metal tracing.
2. Measure GLES draw-wrapper overhead. `klfb_note_draw` performs a live GL
   binding query and thread-ID/census work per draw, and DrawElements formats
   an error detail even when its probe is disabled. The helper also updates
   `g_last_draw_fb`, which a capture path consumes: an unconditional early
   return would change behavior. Keep capture tracking when gating diagnostics.
3. Index per-image ELF symbols while preserving first-match and unload behavior.
   Validate every exported-symbol result against the linear implementation,
   then measure dependency/level loading with real guest libraries.
4. Compare the same game/build/settings and scene on the headset, with warm
   shader caches and logging settings held fixed. Record median/p95/p99 guest
   CPU frame time, GPU duration, stale-frame runs and pose age (the compositor's
   `[cp] timewarp` log already reports the latter two), memory headroom and audio
   underruns. Include a level-load burst: the PR's 250 ms memory-pressure poll
   latency is not yet validated against rapid allocation/jetsam behavior.

Reproduce: `make check-host`, `make check-host-O2`, `make perf`,
`make perf-O2`, `make xros-device xros-sim`. Run timings separately from builds.
